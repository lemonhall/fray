# FRAY 线协议（HTTP + WebSocket）

这是前后端之间**全部**的通信面。没有别的东西：没有轮询长连接、没有 RPC 框架、
没有二进制编解码。你打开 DevTools 的 Network 面板，就能逐条读完一局比赛的全过程。

两条通道分工明确：

| 通道 | 承载 | 为什么 |
|---|---|---|
| HTTP | 身份、房间列表、建房、快速匹配、排行榜、战绩 | 请求-响应式，天然适合 HTTP，可被任何语言/脚本调用 |
| WebSocket | 房间名册、开打、地图、快照、事件、结算 | 一局是"持续双向低延迟流"，HTTP 表达不了 |

---

## 一、HTTP：进门与找桌子

所有接口都在 `/v1/:tenant/...` 下。`:tenant` 是租户 id，**每个 URL 都带着它**——
这是多租户在协议层留下的唯一痕迹：同一个 Worker、同一个域名，换一个租户段就是
另一个互不可见的房间宇宙。

### 1. 拿一张游客令牌

```
POST /v1/{tenant}/guest     { "name": "柠檬叔" }
→ 200 { "playerId": "g_7fQ2...", "name": "柠檬叔", "token": "eyJ...", "tenant": "neon" }
```

打开页面的第一件事。`token` 是**无状态 HMAC**（payload = tenantId + playerId + name），
Worker 不存 session、不查库，验签即认。代价是没法主动失效——对一个不涉及资产的
游客身份，这笔买卖划算。

> 想接自己的账号体系？用带服务端密钥的 `POST /v1/{tenant}/sessions`，把你自己系统里
> 的 `playerId` 换成同一张令牌。协议不变，前端只改一个取 token 的地方。

### 2. 列房间 / 排行榜 / 最近战绩

```
GET /v1/{tenant}/rooms              → { rooms: [ { id, name, mode, phase, humans, bots, capacity, host } ] }
GET /v1/{tenant}/leaderboard?limit=8
GET /v1/{tenant}/matches?limit=8
```

房间列表由**这个租户的 Lobby Durable Object** 独家持有（见 architecture.md 的"为什么
目录要单点"）。前端每 4 秒拉一次，不是长连接——列表慢 4 秒没人受伤，为它维持一条
常驻连接会把复杂度拉回十年前。

### 3. 建房 / 快速匹配

```
POST /v1/{tenant}/rooms        Bearer <token>
  { "name": "午夜码头", "mode": "control", "difficulty": 1, "bots": 4 }
→ 201 { "ok": true, "roomId": "YRC7J5" }

POST /v1/{tenant}/quickmatch   Bearer <token>
→ 200 { "ok": true, "roomId": "QJWRB2", "reused": true }   // 有合适房间就直接复用
```

服务端会拿**租户规则**再夹一遍 `bots`（不信客户端报的数）。建房时 `Room` DO 里就已经
写好了名册骨架与房主身份，所以拿到 `roomId` 之后直接连 WebSocket 就行。

### 4. 管理面（可选）

```
POST /v1/tenants      Bearer <ADMIN_KEY>   { "id": "neon", "displayName": "霓虹前线" }
GET  /v1/tenants
GET  /v1/health
```

`POST /v1/tenants` 是**唯一**需要 `ADMIN_KEY` 的接口：开一个新租户（新游戏）时调一次，
之后那个租户的所有游戏流量都不需要任何密钥。

## 二、WebSocket：一局比赛

连接地址：

```
GET /v1/{tenant}/rooms/{roomId}/socket?token=<token>     （Upgrade: websocket）
```

令牌在 **Room DO 内部**校验（DO 的名字里已经带了租户，它自己就知道该跟谁比），
Worker 层只是把请求原样转交。校验不过直接 401，连握手都不给。

### 客户端 → 服务端

| `t` | 载荷 | 频率 | 说明 |
|---|---|---|---|
| `in` | `{k,a,f,act,r}` | **25Hz** | 输入意图：`k` 移动位(1上/2右/4下/8左)、`a` 瞄准弧度、`f` 是否开火、`act` 一次性动作(1闪避/2装置/4大招)、`r` 射程。**坐标从不上行。** |
| `hero` | `{i}` | 换人时 | 选角色 0–3 |
| `gadget` | `{id}` | 换装置时 | `grenade` / `shield` / `heal` |
| `bots` | `{n}` | 房主点一次 | 投放几个机器人（非房主发送会被直接忽略） |
| `config` | `{mode?,difficulty?,name?}` | 房主点一次 | 换模式/难度（非房主忽略） |
| `start` | — | 房主点一次 | 开局；不满足条件回 `error` |
| `reset` | — | 房主点一次 | 结算后重开一局 |
| `perk` | `{id}` | 升级时 | 三选一的选择 |
| `ping` | `{id}` | 2Hz | 量 RTT，兼作"世界别停"的兜底 |

### 服务端 → 客户端

| `t` | 载荷 | 频率 | 说明 |
|---|---|---|---|
| `hello` | `{you, room}` | 连上时 1 次 | 我的身份 + 房间名册首帧 |
| `room` | 同 `hello.room` | 名册/配置/阶段变化时 | 名册、房主是谁、阶段、机器人数量。**权限的界面投影**由它驱动 |
| `begin` | `{room}` | 开局 1 次 | "切到竞技场"的信号；此时还没有地图 |
| `map` | `{grid, boxes, seed, mode, difficulty}` | 开局 1 次（中途加入的人单独补发） | 地图：31×31 网格压成一个字符串，墙体/草丛由客户端按同一规则重建 |
| `s` | 快照 | **20Hz**（50ms 节流） | 见下 |
| `over` | `{results}` | 一局 1 次 | 结算：名次、击杀、伤害、奖励、构筑 |
| `pong` | `{id, now}` | 回 `ping` | 心跳应答 |
| `error` | `{error}` | 出错时 | `room_full` / `need_two` / `no_players` / `too_many` |

### 快照 `s` 里到底有什么

```jsonc
{
  "t": "s", "tk": 412, "ph": "live", "tm": 6.9,
  "sc": [34, 28],                                   // 两队比分
  "z":  { "x": 992, "y": 992, "r": 158, "ow": 0, "ct": 1 },   // 热点：位置/半径/归属/是否争夺中
  "rg": { "x": 992, "y": 992, "r": 9999 },          // 风暴圈（荒野生存用）
  "a":  [ /* 我能看见的角色。草丛里藏着的敌人**根本不在这个数组里** */ ],
  "b":  [ /* 子弹：[id,x,y,vx,vy,r,ownerId,superShot,hero,team] */ ],
  "bx": [ /* 被打过或被打碎的箱子，客户端据此更新预测用的障碍物 */ ],
  "cb": [ /* 掉落的能量方块 */ ],
  "gr": [ /* 手雷 */ ], "fd": [ /* 力场 */ ], "sp": [ /* 空投 */ ],
  "ev": [ /* 表现层事件：击杀播报、命中跳字、爆炸、屏幕震动 */ ]
}
```

`a[]` 里每个角色字段都短到一眼能扫完：

```jsonc
{ "i": 7, "n": "柠檬叔", "k": 1, "h": 0, "tm": 0, "ow": "g_7fQ2...",
  "x": 992.4, "y": 1504.1, "an": 1.571, "hp": 3120, "mh": 4400,
  "al": 1, "sh": 0, "dk": 0, "cu": 2, "ki": 3, "wl": 12.4, "fl": 0, "hf": 0, "rs": 0 }
```

当 `ow === 我自己的 playerId` 时，报文里会**多一组只有我能看的字段**：
弹药 `am`、大招能量 `su`、装置冷却 `gc`、当前装置 `gd`、累计伤害 `dd`、
冲刺冷却 `dc`、收集数 `co`、占点秒数 `cp`、等级/经验 `lv/xp/nx`、
已拿强化 `pk`、待选强化 `of`。别人的快照里没有这些——不是"我没显示"，
是**根本没发出去**。

### 频率总账（一局 6 人）

| 方向 | 流量 |
|---|---|
| 每客户端上行 | 25 次 `in`/秒 + 0.5 次 `ping`/秒 ≈ 26 条/秒 |
| 服务端下发 | 20 次 `s`/秒 × 6 人（每个客户端收到的是**为他定制**的快照） |
| 合计（6 人房间） | 上行 ~156 条/秒、下行 ~120 条/秒 |

一个设计细节值得说明：服务端**不会**因为收到一条输入就立刻给所有人广播。
50ms 的节流窗口负责节奏，否则 6 个人各 25Hz 上行就会变成 150 次/秒的全员广播。
而心跳也会推进世界——这是"所有人在切标签页"时的第二道保险。
